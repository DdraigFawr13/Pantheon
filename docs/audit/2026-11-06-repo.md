## Fix strongly recommended

### F1 The play guard's `cd` prefix lets any command through

- **Rework if left:** high
- **Effort:** S
- **Evidence:** `.claude/hooks/play-guard.mjs:17` "const BASH = /^(?:cd\s+\S+\s*&&\s*)?(?:uv run"
- **Case:** `\S+` after `cd` matches `;`, `${IFS}` and globs. I fed the hook the command `cd x;cat${IFS}world/s?cret/f&&uv run -q pantheon session` with `data/.playing` present, and it allowed it. The word "secret" never appears literally, so the `secret|sealed` test on line 27 misses it too. During play, the narrator session could put secret or sealed canon into its context. That breaks NAR-02 and WLD-04, which D-041 relies on this guard to keep.
- **Fix:** Drop the optional `cd` group; the play skill never needs it. Or limit the directory to `[\w./-]+`. Add the probe above as a test case.

### F2 The play guard never runs on MCP tools, WebFetch or Skill

- **Rework if left:** high
- **Effort:** M
- **Evidence:** `.claude/settings.json:25` "Bash|Read|Write|Edit|Grep|Glob|Agent|NotebookEdit"
- **Case:** The hook runs only for the eight tools listed. `verdict()` also allows anything it does not know (the `default` branch at line 44). During play, the narrator can call the GitHub MCP file reader on `world/secret/` or `world/sealed/` and the guard never sees it. The same goes for WebFetch, Skill, MultiEdit and Task. D-041's claim that secret canon stays out of the narrator's context does not hold for these tools.
- **Fix:** Match every tool in settings (`.*`). Make `verdict()` deny by default while `.playing` exists, with an explicit allowlist: Bash, Read, Write and Edit as now, plus the artifact and harmless built-in tools the play skill uses.

### F4 A failed `session create --fresh` leaves an empty timeline as the latest

- **Effort:** S
- **Evidence:** `src/pantheon/ui/cli/session.py:687` "affinities = innate_affinity_options(sim, args.people)"

### F5 The check notice prints the raw chance, not the odds the menu showed (D-036)

- **Rework if left:** medium
- **Effort:** S
- **Evidence:** `src/pantheon/narrator/notices.py:21` "{payload['chance']}% chance"

### F6 A new timeline is written in two transactions

### F7 `saves.sh pull` treats a network failure as "no saves branch"

- **Rework if left:** medium
- **Effort:** S
- **Evidence:** `scripts/saves.sh:13` "git ls-remote --exit-code --heads origin saves >/dev/null 2>&1 || return 1"
- **Case:** `ls-remote --exit-code` exits 2 only when the branch is missing. When offline, or on an auth error, it also takes `return 1`. `pull` then prints that a new game starts here and exits 0, while the real save is still on the remote. In a fresh cloud container, the owner starts over without knowing. The later `push` has no parent and is rejected as not a fast-forward. No data is lost, but play continues on the wrong save.
- **Fix:** Return "missing" only on exit code 2. For any other failure, stop `pull` with an error.
