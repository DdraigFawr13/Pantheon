# Audit: pre-M0 scaffold (2026-10-30)

Scope: every tracked file at `b3a519b` (spec, architecture, roadmap, narrator prompt, config, world canon). No code exists yet, so this audits the design. Findings are ranked by how much rework they cause if left until after M1. Status of each: **Proposed** until the owner approves (SRC-04). Nothing here has been changed in the spec or canon.

Method: read in full `docs/SPEC.md` (was `CLAUDE.md`), `docs/architecture.md`, `docs/roadmap.md`, `prompts/narrator.md`, `world/power_tiers.md`, `world/protagonist_seed.md`, `config.example.toml`; read the frontmatter of every `world/` file and grepped the rest of `world/` for mechanics terms (`cap`, `clock`, `shrine`, `tier N`, `level`, `year`, `segment`). Lore prose was not reviewed for story quality.

## A. Fix before M1 (engine design)

1. **The narrator picks the size of rewards and damage.** `grant_xp(amount)`, `adjust_standing(delta -20..+20)` and `apply_effect(amount?)` (`docs/architecture.md:102-105`) let the model choose numbers; the engine only clamps them. That contradicts the project's own principle "the engine owns the numbers" (`README.md:7`) and GAME-03 ("AI text ... never changes stats, rewards"). A model that drifts generous inflates XP within the caps. **Recommend:** the narrator names a *kind* (`grant_xp(kind="milestone_minor", reason)`, `apply_effect(source="check:<id>")`) and an engine table maps it to the number. Damage comes from the check that caused it.

2. **Events must record outcomes, not requests, and carry a rules version.** ENG-06 says state is derived by replaying the log (`docs/SPEC.md:20`), and the `event` table has `rules_version` (`docs/architecture.md:86`), but nothing says what replay does when rules change. If events store requests (`request_check(...)`) replay re-rolls under new rules and old saves change history. **Recommend:** events store resolved results (roll, total, outcome, deltas); replay is a pure fold over results; GAME-05 save versioning with upgraders keyed on `rules_version`.

3. **Forks lose everything that isn't an event.** ENG-08 copies "the event log ... and the RNG state" (`docs/SPEC.md:22`). But `turn` (narration, needed for layer 7 recent turns), `summary` (LLM output, not reproducible, MEM-02 says "stored, not regenerated") and the `hook`/`npc` tables (`docs/architecture.md:88-92`) are not events. A fork would have no recent turns and no chronicle. **Recommend:** state that `hook`, `npc`, released-secret and clock tables are projections rebuilt from events, and that a fork also copies `turn` rows `<= N` and `summary` rows with `span_end <= N`.

4. **Missing tool contracts for state the spec says the engine owns.** ENG-01 lists currency and inventory (`docs/SPEC.md:15`), and the event list has `item_changed` and `trial_resolved` (`docs/architecture.md:94`), but the tool table (`docs/architecture.md:100-113`) has no tool for coin/items, time passing, resolving a Trial, Oath breach, Scars, or Downed/death. Searched the tool table for `coin`, `item`, `time`, `trial_resolved`, `breach`, `scar`, `downed`: no tool. **Recommend:** add `adjust_inventory`, `advance_time`, `resolve_trial`, `resolve_oath_conflict`, and a death/Downed path before M1 freezes the event schema.

5. **In-world time is not engine state.** Oath Boons and Burdens are time-based ("one failed check per day", "30 days", "for a season": `world/power_tiers.md:90-94`), clocks "advance with elapsed time" (`world/factions.md:78`), and Reckoning advances the world 30 days (`world/power_tiers.md:123`). The architecture has no calendar in the state model and no `time_advanced` event. GAME-01 also requires engine time to be injected, never read from the wall clock. **Recommend:** an in-world calendar (day counter, 1,140 AS start per `world/00_overview.md:30`) advanced only by events.

6. **ENG-05 needs an input the tool doesn't take.** The auto-fail rule applies only to "a direct-force action" (`docs/SPEC.md:19`), but `request_check` has no field saying whether the action is direct force (`docs/architecture.md:102`). **Recommend:** add `approach: "force" | "other"` and have the engine validate the `overcome` claim it can check (Standing >= 60, Artifact tier, Ally tier).

7. **Turn-loop sketch skips NAR-06 and can end with no prose.** `docs/architecture.md:52-57` loops `MAX_TOOL_ROUNDS` with no per-call retry counter (NAR-06 caps retries at 2, `docs/SPEC.md:31`); if the cap is hit while the model is still calling tools, `reply.text` is empty and gets recorded. It also holds the SQLite write transaction open across network calls. **Recommend:** count rejections per tool call; on exhausting rounds, force a final no-tools completion; do LLM calls outside the DB transaction and commit events + turn in one short transaction at the end (still atomic per OPS-03).

## B. Fix before M2 (narrator)

8. **Suggested actions are parsed from prose.** The prompt asks for "a numbered list" after the narration (`prompts/narrator.md:79`). NAR-03's "at least one non-violent, one with visible cost" can't be checked from free text. **Recommend:** a `suggest_actions` tool (or structured output) with `kind` and `cost` fields the engine validates.

9. **No fallback when the model is unavailable.** GAME-03 requires a template fallback for every AI surface. OPS-03 only protects the log. **Recommend (needs owner call):** an engine-rendered fallback turn (the check result in plain words plus the last suggested actions), or override GAME-03 for the narrator because the game is the narration. See the open question in `docs/HANDOFF.md`.

10. **Dynamic context sits inside the system prompt.** The template puts state, chronicle, recent turns and player input as placeholders in one system prompt (`prompts/narrator.md:56-76`), and the turn loop sends `messages = [prompt]` (`docs/architecture.md:51`). Recent turns belong in the message list; the cache breakpoint must sit right after canon core (layer 2) or the dynamic tail breaks cache reuse. The "Output" section after the placeholders (`prompts/narrator.md:77-79`) should move above them so the cached prefix holds all instructions. Also check the provider's minimum cacheable length: layers 1 and 2 are about 17 KB on disk (estimate at 4 characters per token: ~4.3k tokens), not the 11.5k tokens budgeted in `docs/architecture.md:70-71`.

11. **NAR-04 is only checked by the live eval.** `docs/architecture.md:138` tests "no unsupplied numbers" only against the live model in M6. **Recommend:** a cheap runtime validator in M2 that scans prose for digits and number words not in this turn's engine results and rejects once (counts toward NAR-06).

12. **Spend ceiling has no prices.** `max_session_spend_usd` (`config.example.toml:9`) needs per-model token prices to enforce. **Recommend:** a `[pricing]` table in config, read with the model ids.

## C. Canon gaps (list in `docs/canon_gaps.md` at M0; don't invent)

13. Skill rank cap at Tier 0 is undefined (`world/power_tiers.md:23` starts at Tier 1), yet every Origin grants a rank-1 skill at Tier 0 (`world/protagonist_seed.md:23-25`).
14. How Level 0 becomes Level 1: does swearing the first Oath set Level 1, or does it need XP? What happens to a player who refuses both offers (`world/protagonist_seed.md:44`)?
15. Oath count above Tier 2 is ambiguous: "a maximum of one additional Oath per two tiers after that" (`world/power_tiers.md:84`): at Tier 4, or Tier 3?
16. "Each hostile round" (`world/power_tiers.md:123`) assumes combat rounds; the engine has no round concept.
17. Tithe "years of life" (`world/power_tiers.md:116`) needs character age, which the character model lacks.
18. `introduce_npc` rejects "tier above region cap" (`docs/architecture.md:109`), but only factions state a highest tier (`world/factions.md:16-72`); most regions in `world/geography.md` don't.
19. Clock time-advance rate is unspecified (`world/factions.md:78`).

## D. Process and tests

20. **GAME-06 vs `hypothesis`.** The roadmap requires replay equivalence "under `hypothesis`" (`docs/roadmap.md:21`); GAME-06 says one determinism test, not seed batteries. These fit if `hypothesis` generates *action sequences* for invariants (replay = live, bounds hold) and determinism stays one fixed-seed test. Recorded as an assumption in DECISIONS.
21. **OPS-05's 90 % line coverage** (`docs/SPEC.md:52`) needs `pytest-cov`, which SPEC section 3 doesn't list. Add it in M0 and record it.
22. **The import rule** (SPEC section 4) should be a plain pytest that walks `engine/` imports, not `import-linter`: one fewer dependency.
23. **Kickoff prompt read everything.** It told the first session to read every file under `world/` including secrets (~28 KB). Changed in this PR to read on demand (CTX-01); secrets are only needed for reveal-gate tests.
